# Заняття 12. Форми в Django

## Приклад задачі
У навчальному проєкті edu_platform "Освітня Платформа" студент хоче поставити питання викладачу. На сторінці він вводить ім'я, email і текст питання. Django перевіряє дані й показує або помилки біля полів, або сторінку підтвердження.

## 1. Що таке Django-форма

У цьому прикладі працюють три частини.

| Частина | За що відповідає |
| --- | --- |
| HTML-форма в шаблоні | Показує поля й кнопку. Браузер надсилає введені значення після натискання кнопки. |
| Клас форми `forms.Form` | Описує поля та правила. Наприклад, email повинен мати коректний формат, а питання має містити щонайменше 10 символів. |
| Функція `view` | Приймає запит, запускає перевірку й вирішує, яку сторінку показати. |

**Валідація** означає перевірку введених даних за заданими правилами. Браузер може відразу підказати, що поле порожнє або email має неправильний формат. Django виконує власну перевірку на сервері, адже запит можна надіслати й поза браузером.

## 2. Описуємо поля в `courses/forms.py`

```python
from django import forms


class TeacherQuestionForm(forms.Form):
    name = forms.CharField(label="Ім'я", max_length=100)
    email = forms.EmailField(label="Email")
    question = forms.CharField(
        label="Питання",
        min_length=10,
        widget=forms.Textarea,
    )

    def clean_question(self):
        question = self.cleaned_data["question"]
        if "???" in question:
            raise forms.ValidationError(
                "Сформулюйте питання без трьох знаків питання поспіль."
            )
        return question
```

- `CharField` приймає текст. `EmailField` перевіряє формат email.
- `label` задає підпис, який бачить користувач. Ім'я поля в Python, наприклад `question`, стає ключем для доступу до даних.
- `max_length` і `min_length` обмежують довжину тексту.
- `widget` визначає, як поле виглядає в HTML. З `forms.Textarea` користувач отримує багаторядкове поле. Правила перевірки задає сам `CharField`.
- Усі три поля обов'язкові за замовчуванням. Для необов'язкового поля можна вказати `required=False`.

Під час валідації Django викликає `clean_question()` після того, як поле `question` пройшло стандартні перевірки. Назва методу має формат `clean_<назва_поля>`. Метод бере вже оброблене значення з `self.cleaned_data` і перевіряє додаткове правило. Якщо текст питання містить `???`, виняток `ValidationError` додає помилку до поля `question`. Якщо все гаразд, `return question` повертає значення, яке залишиться в `cleaned_data`.

## 3. Обробляємо відкриття й надсилання форми

Додайте до `courses/views.py` функцію `ask_teacher` і потрібні імпорти.

```python
from django.shortcuts import render

from .forms import TeacherQuestionForm


def ask_teacher(request):
    if request.method == "POST":
        form = TeacherQuestionForm(request.POST)

        if form.is_valid():
            return render(
                request,
                "question_sent.html",
                {"data": form.cleaned_data},
            )
    else:
        form = TeacherQuestionForm()

    return render(request, "ask_teacher.html", {"form": form})
```

| Що робить студент | Що робить Django |
| --- | --- |
| Відкриває `/ask-teacher/` | Браузер надсилає `GET`. `TeacherQuestionForm()` створює порожню форму для першого показу. |
| Натискає "Надіслати" | Браузер надсилає `POST`. `request.POST` містить значення полів. `TeacherQuestionForm(request.POST)` створює форму, зв'язану з цими даними. |
| Надсилає коректні дані | `form.is_valid()` повертає `True`. View передає перевірені дані з `form.cleaned_data` у шаблон підтвердження. |
| Надсилає дані з помилками | `form.is_valid()` повертає `False`. View передає **той самий об'єкт** `form` назад у шаблон. Студент бачить введений текст і повідомлення про помилки. |

Успішна перевірка дає змогу працювати з `form.cleaned_data` як зі звичайним словником. Наприклад, `form.cleaned_data["question"]` містить перевірений текст питання. Django також перетворює значення на відповідні типи Python. Наприклад, для `IntegerField` введене `"12"` стає цілим числом `12`. Помилки можна переглянути в `form.errors`.

Для пошуку або фільтрації зазвичай підходить `GET`: значення передаються в URL, а Django читає їх із `request.GET`. Для надсилання питання використовуємо `POST`: значення полів передаються в тілі запиту.

## 4. Підключаємо адресу й шаблони

У `courses/urls.py` додайте до наявного списку `urlpatterns` рядок нижче. Якщо імпорту `views` ще немає, додайте `from . import views` на початку файлу.

```python
path("ask-teacher/", views.ask_teacher, name="ask_teacher"),
```

Створіть `courses/templates/ask_teacher.html`.

```html
{% extends "courses/base.html" %}

{% block main %}
    <h1>Питання до викладача</h1>

    <form method="post">
        {% csrf_token %}
        {{ form.as_p }}
        <button type="submit">Надіслати</button>
    </form>
{% endblock %}
```

- `method="post"` вказує браузеру метод запиту. Без `action` браузер надсилає форму на поточну адресу `/ask-teacher/`.
- `{% csrf_token %}` додає приховане поле з токеном. Django перевіряє його під час `POST`, щоб захистити сайт від підроблених запитів з інших сайтів. Якщо токен відсутній або некоректний, Django може повернути помилку `403 Forbidden`.
- `{{ form.as_p }}` виводить підписи, поля й помилки. Тег `<form>` і кнопку додаємо в шаблоні.
- `{% block main %}` відповідає назві блоку в `courses/base.html` навчального проєкту. У власному проєкті використовуйте назву блоку зі свого базового шаблону.

Створіть `courses/templates/question_sent.html`.

```html
{% extends "courses/base.html" %}

{% block main %}
    <h1>Питання прийнято</h1>
    <p>Дякуємо, {{ data.name }}!</p>
    <p>Ваше питання: {{ data.question }}</p>
{% endblock %}
```

View передає словник під іменем `data`, тому в шаблоні `{{ data.question }}` показує текст питання. На занятті 12 підтвердження означає, що дані пройшли перевірку. Щоб викладач отримав питання, потрібна окрема дія у view, наприклад надсилання листа.

## 5. Перевірте приклад у браузері

Запустіть `python manage.py runserver` і відкрийте `http://127.0.0.1:8000/ask-teacher/`. Для перевірки тексту питання заповнюйте ім'я й використовуйте коректний email, наприклад `student@example.com`.

| Дія | Очікуваний результат |
| --- | --- |
| Відкрити сторінку | З'являються три порожні поля без помилок. |
| Ввести в поле питання `Привіт` | Браузер може зупинити надсилання. Якщо запит дійде до Django, форма покаже помилку мінімальної довжини. |
| Ввести `Коли почнеться курс???` | Django покаже помилку біля питання. Введені значення залишаться у формі. |
| Ввести `Коли почнеться новий курс?` | Відкриється сторінка підтвердження з іменем і текстом питання. |

У власному проєкті можна використати цей самий підхід для відгуку, заявки чи повідомлення. Спочатку визначте поля та їхні типи, потім додайте одне правило, яке має сенс для вашого проєкту. Наприклад, для заявки на подію дата участі має бути сьогодні або пізніше.

**Що буде далі.** На наступному занятті з'явиться `forms.ModelForm`. Вона може створити поля на основі моделі й після валідації зберегти об'єкт через `form.save()`.

## Питання для самоперевірки

1. Яка різниця між `TeacherQuestionForm()` і `TeacherQuestionForm(request.POST)`?
2. Чому після невдалої перевірки view повертає в шаблон той самий об'єкт форми?
3. Де перевіряється правило про три знаки питання поспіль і біля якого поля з'явиться помилка?
4. Звідки view бере перевірені дані після успішного `is_valid()`?
